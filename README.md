# Button Levels

Внутрішній пакет команди для платформи **Colo**. Формат доставки — **DOCKER**
(живий веб-сервіс). Цей README — для організаторів; учаснику передається **лише URL**
запущеного сервісу. Детальний розбір — у `walkthrough.md`.

## Ідентифікатор і навчальна мета
- **ID:** `button-levels`
- **Модуль:** Web, beginner → intermediate
- **Роль:** автор завдання
- **Формат:** DOCKER (Flask + gunicorn)
- **Навчальна мета:** клієнтський бік не можна довіряти. По рівнях: читання джерела
  (HTML-коментар), Service Worker Cache, client-side template injection (CSTI),
  `disabled` як несправжній захист + правка DOM, автоматизація консоллю за багатьох
  елементів, підміна ціни/параметрів (client-side price tampering), обхід капчі,
  перевіреної на клієнті.

## Що отримує та робить учасник
Отримує **URL живого сервісу** (жодних файлів). Проходить `/login` (ім'я `Alice` + пароль
з HTML-коментаря), далі 5 рівнів: прапор рівня N — пароль, що відкриває рівень N+1.
Порядок нав'язує сам сайт (сесія + `POST /level/<n>/unlock`). Питання кожного рівня видно
на його сторінці.

## Файли й доступ до них
**В образі (доступне учаснику через сервіс):**
- `app.py` — маршрути, рівні (SSOT: список `LEVELS`), логіка вразливостей
- `templates/` — сторінки рівнів, кат сцени, логін
- `static/` — `alice.js`, `style.css`, `sw.js`, шрифти, гіфки, зображення
- `Dockerfile`, `requirements.txt` — контекст збірки

**Внутрішнє (НЕ в образі — виключено в `.dockerignore`):**
- `README.md` (цей файл), `walkthrough.md` (приватний розбір), `remote_solver.py` (еталонний
  солвер), `plans/` (робочі плани), `docker-compose.yml` (локальний запуск із демо-ключами)

## Питання та оцінювання
П'ять ключів `type=flag`, по одному на рівень, у порядку 1→5. Значення — реальні прапори,
що на платформі приходять як `LAB_KEY_1 … LAB_KEY_5` (локальні демо — у `docker-compose.yml`).

| # | Рівень | Питання (на сторінці рівня) | Формат відповіді |
|---|--------|------------------------------|------------------|
| 1 | Just Press It | Натисни кнопку, яка тікає від миші | `COLO_FLAG{...}` |
| 2 | Flag Removed | Знайди прапор, прибраний зі «свіжої» сторінки | `COLO_FLAG{...}` |
| 3 | Parrot | Змусь Alice вимовити її секрет | `COLO_FLAG{...}` |
| 4 | Twitchy | Заспокой мишу, обійди `disabled`, знайди справжню записку серед 50 | `COLO_FLAG{...}` |
| 5 | Corner Shop | Купи пиво за 1000 ₴, маючи 100 ₴, і обійди капчу | `COLO_FLAG{...}` |

Ключі приймаються в довільному порядку; просування по сайту все одно послідовне.
Демо-значення та покрокові рішення — у `walkthrough.md`.

## Збірка або генерація
Передумови: Docker + Docker Compose. Робочий каталог — корінь пакета.
```sh
docker compose up -d --build
```
Env (compose задає демо-значення; на платформі — через конфіг ключів CTFTask):
- `LAB_KEY_1 … LAB_KEY_5` — прапори рівнів (fallback `FLAG_1 … FLAG_5` для локалки)
- `LOGIN_PASSWORD` — пароль логіна (у HTML-коментарі сторінки)
- `SECRET_KEY` — підпис session-cookie (тримати стабільним між рестартами)
- `LAB_RUN_ID` — контекст запуску (логується на старті)

Застосунок **гучно падає**, якщо бракує обов'язкового env (`require_flag`/`require_env`).
Внутрішній порт — **5000**. Готовність — `GET /colo-health` → `200 ok`.

## Перевірка та зупинка
```sh
# готовність
curl -i http://127.0.0.1:5000/colo-health        # 200, тіло: ok

# еталонний солвер — лише через інтерфейс учасника, друкує ANSWER_1..5, exit 0 лише коли всі
python remote_solver.py --url http://127.0.0.1:5000

# зупинка
docker compose down
```
Очікуваний вивід солвера (демо-ключі):
```
ANSWER_1: COLO_FLAG{d0nt_n33d_4_m0us3}
ANSWER_2: COLO_FLAG{c4ch3_n3v3r_f0rg3ts}
ANSWER_3: COLO_FLAG{sh3_r3p34ts_t00_much}
ANSWER_4: COLO_FLAG{th3_m0us3_f1n4lly_c4lm3d_d0wn}
ANSWER_5: COLO_FLAG{n3v3r_tru5t_cl13nt_pr1c3}
```

## Реєстрація на платформі
- **Тип доставки:** DOCKER; вхідний сервіс із контексту збірки (`Dockerfile`, корінь `.`).
- **Внутрішній порт:** 5000 (платформа публікує його на хост сама).
- **Маршрут готовності:** `GET /colo-health` (200 `ok`).
- **Ключі:** 5 × `type=flag`, значення = прапори рівнів, подаються через `LAB_KEY_1 … LAB_KEY_5`.
- **Приватний розбір:** `walkthrough.md` → `Lab.solution_walkthrough`.
- Не публікувати внутрішні файли та реальні секрети; демо-ключі позначені як демо.

## Результати перевірки
Локально (gunicorn/flask, порт 5000), перевірено:
- `GET /colo-health` → **200**, тіло `ok`.
- `remote_solver.py --url …` → друкує **ANSWER_1…5** (= реальні прапори), **exit 0**.
- Пріоритет ключів: заданий `LAB_KEY_1` перекриває `FLAG_1` (перевірено).
- Негативний випадок: недосяжний прапор → гучна помилка в stderr, **exit 1**.
- `LAB_RUN_ID` логується на старті.

Налаштовано (перевірено за конфігом, не збіркою — образ будуєш локально):
- `.dockerignore` виключає з образу `README.md`, `walkthrough.md`, `remote_solver.py`,
  `plans/`, `docker-compose.yml`, `__pycache__/`.
- `HEALTHCHECK` в `Dockerfile` і `docker-compose.yml` опитує `/colo-health`.
- Ліміти: `mem_limit 256m`, `cpus 0.5`, `pids_limit 128`, `no-new-privileges`; сервіс
  працює під non-root користувачем `ctf`.
